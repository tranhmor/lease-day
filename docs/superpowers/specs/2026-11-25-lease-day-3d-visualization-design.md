# 《到期日》v0.7 三维可视化设计方案

> **用途**：交给前端 / 三维开发者实施的设计说明书。
> **日期**：2026-11-25　**状态**：设计稿，待组内确认
> **视觉参考**：用户提供的“深圳的一天”城市大屏（深色、倾斜视角的三维城市底图、发光路网、粒子、同心波纹，四角为数据面板，底部是时间轴）。
> **可运行的二维概念稿**：`docs/viz/concept-v1.html`。版面、面板分工和交互逻辑以它为准；本文把它升级为三维版。

## 0. 一句话目标

做一个**离线运行的三维“租赁市场 36 个月回放”大屏**，让观众在 60 秒内看懂：

> 新地铁线**公告后、开通前**，LLM 扮演的房东有没有提前涨价（H1）？谁提前搬进了受益区（H2）？LLM 房东是不是太好说话（H3）？

同一套程序要服务三个出口：

| 出口 | 用法 | 对应阶段 |
|---|---|---|
| 报告（英文，< 5,000 词） | 导出 4K 静帧，作为 1–2 张主视觉；统计图仍由 `figures_v07.py` 生成，共用同一套配色 | A |
| 课堂汇报 PPT | 关键月份静帧 + 一段 60 秒录屏（作为现场演示的备份） | A / B |
| 现场原型演示 | 浏览器全屏：播放、切换情景、点房间看 LLM 理由，最后现场问房东 | B → C |

## 1. 设计原则

1. **地图是舞台，LLM 理由是主角。** 三维效果服务于“在哪里发生”，理由文本回答“为什么发生”。理由面板不能被视觉特效挤掉。
2. **三种情景是同一座城市。** N / S / P 共用同一批人和同一套随机事件，差别只在“有没有公告”。界面上必须一眼看出这一点：切换情景时城市不重建，只有数据变化。
3. **颜色有固定含义，全程不变。** 琥珀色只用于“新线 / 公告”，红色只用于 P，蓝色只用于 S，灰色只用于 N。
4. **诚实优先于好看。** 区内房间位置是示意；示意数据要打水印；理由流按固定规则抽样，不能挑选；显示置信区间（见第 9 节）。
5. **离线、稳定。** 教室网络不可靠：不依赖在线瓦片和 CDN，所有资源打包在本地。

## 2. 技术路线（三选一，推荐 A）

| | A · Three.js 自绘（推荐） | B · deck.gl + MapLibre | C · 2D 增强（D3 + Canvas） |
|---|---|---|---|
| 效果上限 | 最高：可自定义着色器、辉光、体积光、粒子 | 中高：自带三维柱、弧线、轨迹图层，辉光需另做 | 中：伪三维（倾斜 + 阴影） |
| 与参考图的相似度 | 能完全还原 | 约 80% | 约 50% |
| 开发量 | 大，约 2–3 周（1 人） | 中，约 1.5–2 周 | 小，约 1 周 |
| 风险 | 性能调优、投影仪上的显卡兼容 | 底图需离线化；风格较“GIS 工具” | 视觉冲击弱 |
| 建议技术栈 | Vite + TypeScript + three（r160 及以上）+ postprocessing + GSAP；界面层用 React 或原生均可（推荐 React + @react-three/fiber + drei，方便和面板联动） | deck.gl 9 + MapLibre GL（自建离线样式）+ React | 在现有 `analysis/viz_dash` 上改 |

**推荐 A**：用户明确要求达到参考图的三维质感，而 Three.js 是唯一能完全控制辉光、波纹、粒子风格的方案。为降低风险，要求开发者实现一个**降级开关**（见 8.3），检测到 WebGL 性能不足时切换为二维俯视、关闭后期特效。

| 章 | 月份 | 镜头 | 画面重点 | 面板 | 旁白（示意） |

## 4. 视觉语言

### 4.1 颜色（设计变量，前端与 matplotlib 共用同一份 `tokens.json`）

| 变量 | 色值 | 含义 |
|---|---|---|
| `bg` | `#0B111C` | 背景，中心叠加径向渐变 `#16233A` |
| `panel` | `rgba(16,24,38,0.78)` + 6px 背景模糊 | 面板底色 |
| `line` | `#24324A` | 分隔线、面板描边 |
| `text` / `sub` | `#E6ECF5` / `#7D8AA3` | 正文 / 次要文字 |
| `cool` | `#5FB4FF` | 默认房间、地铁、面板左上角的强调短线 |
| `announce` | `#FFB02E` | **只用于新线和公告**，包括理由高亮 |
| `P` / `S` / `N` | `#FF6B57` / `#4EA8FF` / `#8A94A8` | 三种情景 |
| `up` / `down` | `#FF8A6B` / `#6BD3A0` | 涨价 / 降价（对租客有利为绿） |
| 租金变化色带 | −4 → 0 → +4 指数点：`#5FB4FF` → `#9AA7BD` → `#FFB02E` → `#FF5A3C` | 发散色带，0 为中性灰，两端对称 |

报告用浅色版：背景 `#FBFAF7`，同一套情景色降低饱和度约 15%。

### 4.2 字体

- 中文：思源黑体（Source Han Sans SC，OFL 许可，本地打包）。
- 数字：等宽字体 JetBrains Mono 或 DIN 风格的 Barlow，Tabular 数字，保证滚动时不跳动。
- 左上角大号月份 `M22/36` 用 200 字重，约 88px（1080p 下）。

### 4.3 动效节奏

- 默认 1 个月 ≈ 1.7 秒，36 个月约 60 秒。可选 0.5× / 1× / 2×。
- 数字变化用 400ms 缓动滚动；脉冲和波纹 1.4 秒淡出；镜头切换 1.5–2.5 秒（GSAP `power2.inOut`）。
- 同屏同时出现的动画不超过 3 类，避免满屏闪烁。

## 5. 三维场景构成

所有坐标统一投影为**以 CBD（双井 Z00）为原点的局部平面坐标**（Web 墨卡托，再换算成米并缩放），Y 轴向上。

### 5.1 图层（从下到上）

| # | 图层 | 数据来源 | 呈现 | 实现要点 |
|---|---|---|---|---|
| L0 | 地面 | — | 深色平面，叠加细网格和 CBD 中心的径向暗角 | 单个平面 + 着色器 |
| L1 | 城市底图 | OSM 导出（需新增）：五环、六环、主干路、区界、水系 | 路网是暗蓝色细线，主干道稍亮；水系为更深的面 | `LineSegments2`（粗线）；预先简化并合并成一个缓冲区 |
| L2 | 建筑体块（可选） | OSM 建筑轮廓，只取 CBD 和受益区周边 | 低多边形挤出，暗色，顶面边缘带细微发光 | 合并几何体；只做 3–4 个片区，控制面数 |
| L3 | 地铁网 | `analysis/bj_routes_full.json`、`stations.json`（已有） | 稍高于地面的发光细管，站点为小光点 | `TubeGeometry` 或粗线 + 辉光 |
| L4 | **东向快线** | 虚构线路：CBD → 定福庄（Z01）→ 果园（Z05）→ 武夷花园（Z11）。需在数据中单独定义 | 公告前不显示；公告后为琥珀色虚线全息样式（扫描纹、半透明）；开通后变实线，光流沿线跑动 | 自定义着色器：`uProgress` 控制生长，`uOpen` 控制虚实 |
| L5 | **房间光柱**（核心） | 240 间房的逐月状态 | 每间房一根细光柱。**高度 = 当月租金**（按房型归一化，见 5.2）；**颜色 = 租金比第 1 月的变化**（4.1 色带）；空置时只留暗色底座和细边框 | `InstancedMesh`，每月更新实例属性；高度和颜色用 600ms 插值 |
| L6 | 区级波纹 | 受益区 P − S 差值 | 果园、武夷花园周围的同心圆波纹（对应参考图的同心环），强度和半径随 P − S 增大 | 平面 + 着色器，`uIntensity` |
| L7 | 通勤流粒子 | 各区在租户的通勤方式和时间 | 粒子沿地铁或道路流向 CBD；流量 ∝ 该区在租人数；速度 ∝ 1 / 通勤时间。开通后受益区粒子明显加速 | GPU 粒子（`Points` + 沿路径的顶点动画） |
| L8 | 搬家弧线 | 迁入和迁出事件 | 从旧房到新房的抛物线弧，颜色按收入组（低 / 中 / 高三色，需和情景色区分），飞行 1.2 秒后消失 | 每个事件一条短生命周期的弧线，用对象池 |
| L9 | 决策脉冲 | `decisions.jsonl` | 本月有 LLM 决策的房间冒出一圈脉冲：普通决策为 `cool`，理由提到新线的为 `announce` | 精灵图 + 缩放 / 透明度动画 |
| L10 | 标签 | 区名 + 指标 | 类似参考图的“福田CBD 55.1万”：主要区显示名称和一行指标（如“+2.5 指数点”），受益区常亮，其余区随镜头距离淡入淡出 | `CSS2DRenderer`，或 troika-three-text（SDF 文字） |

### 5.2 房间的布局与编码

- 房间没有真实坐标。每个区内用**向日葵（phyllotaxis）排布**，以真实区质心为圆心，半径 ∝ √房间数。相邻区重叠时向外推开，沿用 `analysis/viz_build.py` 里已有的推开算法。画面角落必须注明“区内位置为示意”。
- 受益区房量做了过度抽样（Z05 24 间、Z11 16 间），视觉上本来就会更密。图例里要写明这是为统计力，避免观众误以为受益区本身房子多。
- 光柱高度：同房型内按租金分位归一化，否则整租会压过合租单间。房型用底座形状区分：整租为方形，合租单间为圆形，低价房为三角形。
- 光柱高度变化要能被看出来，但不能夸张：最大高度差控制在画面高度的约 8%。

### 5.3 镜头

- 默认：俯仰 55°，视场角 35°，以 CBD 偏东为中心，让受益区落在画面右侧三分之一处，给左侧面板留出空间。
- 每章一个关键帧（位置、目标点、视场角），由 GSAP 插值。
- 探索模式：`OrbitControls` 限制俯仰在 25°–80° 之间，缩放和平移都设边界，防止迷失。
- 空闲 20 秒后缓慢自动环绕（每分钟约 6°），参考图的“呼吸感”。

### 5.4 后期与氛围

- 辉光（UnrealBloom 或 pmndrs postprocessing 的 `SelectiveBloom`）：**只作用于**地铁、新线、脉冲和高光柱，强度适中，避免整屏发糊。
- 雾效：指数雾，让远处路网自然消失。
- 色彩分级：轻微的青色暗部 + 暖色高光；可选少量胶片颗粒（不超过 3%）。
- 不做实时阴影（性能开销大），用接触阴影贴图代替。

## 7. 交互规格

### 7.1 三种模式

| 模式 | 用途 | 行为 |
|---|---|---|
| 演示模式（默认） | 课堂汇报 | 按 → / ← 切换章节；镜头、图层、面板全部由脚本控制；鼠标操作不打断脚本，按 Esc 退出到探索模式 |
| 探索模式 | 问答环节、老师自己点 | 自由播放、拖动、切换、点击 |
| 导出模式 | 产出报告和 PPT 素材 | URL 参数 `?export=1&month=18&scen=P&chapter=4&w=3840&h=2160`；隐藏光标；一键导出 PNG；可选按帧录制成 MP4（用 CCapture.js 或 WebCodecs） |

### 7.2 键盘

`Space` 播放 / 暂停 · `← →` 上一月 / 下一月（演示模式下为上一章 / 下一章）· `1 2 3` 切换 N / S / P · `D` 分屏对比 · `L` 打开“问房东”面板（C 阶段）· `F` 全屏 · `H` 隐藏所有界面（只留城市，便于截图）。

### 7.3 分屏对比（P − S 的核心视图）

- 视口竖切成左右两半：左 S、右 P，两个视口的镜头**完全同步**。
- 中间是可拖动的分隔线，体验类似“卷帘对比”。
- 也可切换为“差值模式”：单个视口，光柱高度 = P − S，颜色为发散色带。

### 7.4 “问房东”面板（C 阶段）

- 右侧抽屉面板。选项：房东类型（个人 / 托管机构）× 风险偏好（怕空置 / 愿意等）、房间（从地图点选）、空置率滑块、公告开关、距开通月数。
- 点“提问”后：先查缓存（以提示词哈希为键），命中立即显示，并标“缓存”；未命中再调用 hy4-flash，标“实时”，显示等待动画。
- 结果卡片：报价、付款方式、理由；和“公告关闭”的同条件结果并排对比。
- **预置 6 组输入**，演示前全部跑好进缓存，确保现场不依赖网络。
- API key 只放在本地后端，前端拿不到（见 8.2）。
- 面板角落固定一行说明：“单次回答具有随机性；结论以 5 个种子的统计结果为准。”

## 8. 数据与工程

### 8.1 数据契约

由 Python 导出脚本（建议新建 `prototype_v07/export_viz.py`）把实验结果转换成前端用的静态文件，前端**只读这些文件**，不直接读 `runs_*`。

```
viz_data/
  meta.json            # 版本、生成时间、情景列表、种子列表、事件月份（13、25）、数据来源、is_illustrative 标记
  geo/
    zones.json         # [{id, name, lat, lon, treated, n_rooms, label_offset}]，来自 analysis/zone_centroids.json + viz_dash/zones.json
    metro.geojson      # 由 bj_routes_full.json 转换并简化
    newline.geojson    # 东向快线，虚构线路，properties: {hypothetical: true}
    basemap.geojson    # 路网 / 区界 / 水系（新增，从 OSM 导出）
  rooms.json           # 240 间房的静态属性：{id, zone, kind, landlord_id, layout_xy}
  landlords.json       # 40 名房东：{id, kind, risk, zones, n_rooms, treated}
  runs/{scen}_{seed}/
    room_states.bin    # 36 × 240 的逐月状态：rent(float32), occupied(u8), tenant_id(i32), vacant_for(u8)
    events.json        # 搬入 / 搬出 / 续租 / 还价：{m, type, tenant_id, from_room, to_room, income_group, rent}
    decisions.json     # 精简版决策：{m, agent_type, agent_id, decision, room_id, zone, rent_before, rent_after, reason, mentions_line, prompt_hash, fallback}
    monthly.json       # 直接来自 monthly.jsonl
  aggregate/
    monthly_ci.json    # 每个情景、每月、每个指标的跨种子均值和 95% CI
    verdicts.json      # H1–H3 判定结果，来自 analyze_v07.py 的 PREREG_L
```

**关于 `room_states` 的缺口**：现有的 `monthly.jsonl` 只有汇总数据，`decisions.jsonl` 只记录 LLM 决策，**目前没有逐月、逐房间的完整状态快照**。建议：

- 给引擎加一个只写日志的开关 `--dump-room-states`，每月末写一行 `room_states.jsonl`。
- LLM 回答全部已缓存，重跑不会产生新的 API 调用。
- **验收条件**：重跑后的 `monthly.jsonl` 必须与原文件逐字节一致，证明这个开关没有改变结果。

`mentions_line` 由导出脚本用固定关键词表判定，词表写进 `meta.json` 以便复核：快线、开通、通车、通勤改善、通勤利好、交通便利、交通将改善、未来利好、溢价、将受益。

### 8.2 运行架构

```
[浏览器：Three.js 前端]  ──读取──▶  viz_data/（静态文件，随包分发）
         │
         └─(仅 C 阶段)─▶  本地后端（FastAPI，127.0.0.1）
                            ├─ 复用 prototype_v07/prompts 的冻结模板
                            ├─ 先查 llm_cache.sqlite，未命中才调用 hy4-flash
                            └─ 从 .env 读取 API key（前端拿不到）
```

- A、B 阶段：纯静态网页，双击 `index.html` 或 `npx serve` 即可运行。
- C 阶段：多一个 `python -m viz_server` 进程。后端不可用时，“问房东”面板自动置灰，其余功能不受影响。

### 8.3 性能目标与降级

| 项目 | 目标 |
|---|---|
| 目标设备 | 集成显卡的笔记本（如 M1 MacBook Air、Intel Iris Xe），外接 1080p 投影 |
| 帧率 | ≥ 50 fps（1080p，全部特效开启） |

| 自动降级 | 启动后前 3 秒平均帧率 < 30 时自动降一档，右下角提示，可手动切回 |

### 8.4 兼容性

Chrome / Edge 最新版为主，Safari 17 及以上可用。所有资源本地化，包括字体、底图、库文件，不允许运行时请求外网，C 阶段的后端调用除外。

## 9. 学术诚信规则（必须实现）

1. **示意数据水印**：`meta.json` 里 `is_illustrative = true` 时，界面底部固定显示“示意数据，非实验结果”，导出的 PNG 也要带上。
2. **理由流不得挑选**：每月从该情景、该种子的全部房东决策中按“受益区 / 其他区”分层随机抽取，随机种子固定，写进 `meta.json`。“提到新线”的比例按**全部**决策计算，不按抽样计算。
3. **默认展示哪个种子**：默认显示“中位种子”，即 P − S 第 24 月值最接近 5 个种子中位数的那个，并注明。总览曲线一律用跨种子均值 + 95% CI。
4. **理由不等于因果**：理由面板标题旁固定一行小字：“LLM 自述理由，用于说明行为，不作为因果证据。”
5. **虚构线路**：东向快线在图例中标注“假想线路”。
6. **区内位置为示意**：见 5.2。
7. **结论卡**（第 7 章）只引用 `verdicts.json` 的预先登记判定，不允许在前端另行计算“显著”。
